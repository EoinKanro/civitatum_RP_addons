# Civitatum Inventory: сохранение исходников

Пользователь поручил сохранять исходники в удалённый Git каждые 10 минут активной работы. Эти правила относятся к доработке этого проекта.

1. Перед изменениями проверь ветку, рабочее дерево, удалённый адрес и доступ к записи. Прочитай `BACKUP_RU.md`. Начни с `python3 tools/git_checkpoint.py once` и дождись `REMOTE_VERIFIED`. Не объявляй локальный коммит или архив отправленным в удалённый Git. В этой среде доступна запись через GitHub connector; обычный Git CLI остаётся без авторизации. Скрипт автоматически использует connector при наличии `.git/civitatum-backup/github-config.json`.
2. При работе дольше 10 минут запусти `python3 -u tools/git_checkpoint.py watch` в отдельном процессе и сохрани его идентификатор. Таймер делает коммит и push каждые 600 секунд; пустых коммитов нет. Он работает только в живой рабочей среде и не переживает её удаление. После восстановления среды запусти его заново.
3. В начале работы и не реже чем раз в 5 минут выполняй `python3 tools/git_checkpoint.py heartbeat`. Это продлевает разрешение таймеру сохранять текущую работу на 20 минут. Без продления таймер остаётся запущенным, но перестаёт делать коммиты.
4. Резервные снимки идут в `codex/checkpoints/civitatum-inventory`. Скрипт использует отдельный индекс, не переключает рабочую ветку и не забирает пользовательские staged-изменения. Не подменяй его без необходимости командой `git add -A` для всего проекта.
5. Проверяй `python3 tools/git_checkpoint.py status`. Успех — `remote_verified: true` для текущего снимка. При ошибке push сообщи об ошибке, сохрани локальный снимок и устрани доступ/расхождение истории. Не применяй force push, reset или переписывание меток выпусков для исправления резервного сохранения.
6. Перед длительной сборкой, большим изменением или завершением работы дополнительно выполни `once`. В конце запроси `stop`, дождись завершения процесса. Незавершённый снимок допустим: его сообщение обозначает checkpoint, а не проверенный релиз.
7. Проверенные выпуски сохраняй отдельными коммитами и метками. `v0.3.0` обозначает исходники выданного и проверенного выпуска. Не переставляй эту метку.
8. Не включай в репозиторий сборочные кэши, тестовые миры, скачанные моды, ключи и данные авторизации. Если удалённый репозиторий ещё не подключён, можно готовить подключение и механизм сохранения; до доступного push сохрани Git bundle во внешнем постоянном хранилище и честно обозначь это ограничение.
9. После потери среды восстанови исходники из GitHub и заново настрой доступ. Для connector получи свежий HostedAppsClient из текущего окружения (Library skill: `scripts/library_hosted_apps.py`), сохрани SDK вне репозитория, определи актуальный connector_id по метаданным доступных GitHub tools. Запиши `repository_full_name`, `connector_id`, абсолютный `sdk_path` и при необходимости `base_branch` в приватный `.git/civitatum-backup/github-config.json`. Не восстанавливай истёкшие токены или чужой connector_id из догадок. При обычной HTTPS-авторизации Git этот конфиг не нужен.
10. Коммиты connector имеют серверные SHA, отличные от локальных коммитов. Сравнивай `source_tree`: оно должно точно совпасть. Исходная локальная история и метка `v0.3.0` сохраняются также в bundle ветки `codex/original-history`. Ветка `codex/releases/v0.3.0` фиксирует проверенные исходники; не передвигай её. Теги через текущий набор connector tools не создаются.

Интервал относится к активной рабочей сессии. Задачи планировщика чата не заменяют этот таймер: они поддерживают частоту не выше одного запуска в час и не гарантируют доступ к живому рабочему дереву.
