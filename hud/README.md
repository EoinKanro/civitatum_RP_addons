# Civitatum HUD 0.4.1

Разработчик: **Civitatum Team**. Независимый клиентский мод для Minecraft **1.21.1**, **NeoForge 21.1.256+**, **Java 21**.

## Установка

Мод раньше назывался Civitatum Inventory (`civitatum_inventory`). Замените его JAR `civitatum-inventory-*.jar` на `civitatum-hud-0.4.1.jar` в папке `mods`; прежний JAR удалите — в нём тот же код, две копии одновременно не загрузятся. Настройки из `config/civitatum-inventory.json` читаются, пока нет нового файла, и при первом сохранении переезжают в `config/civitatum-hud.json`. Назначенные клавиши мода хранятся в `options.txt` под старыми именами (`key.civitatum_inventory.*`), поэтому после переименования они возвращаются к значениям по умолчанию. Civitatum Character Creation и остальные интеграции устанавливаются отдельно. Для доступа к предметам стороннего мода сам этот мод должен присутствовать на сервере.

В версии 0.4 используются новые ключи раскладки: прежние большие окна не переносятся автоматически. Прозрачность, размер слотов, выбранная способность и расположение окон сохраняются в `config/civitatum-hud.json`.

## Настройки

Экран настроек — в списке модов: Esc → Mods → Civitatum HUD → Config (или то же из главного меню). «Готово» возвращает в список модов. Изменения сразу пишутся в `config/civitatum-hud.json` (поле `hotbarStyle`).

**Хотбар:**

- **Morrowind** (по умолчанию) — как раньше: у полосок в левом нижнем углу только предмет в руке, выбранная способность и дополнительная рука.
- **Классический** — снизу по центру одной полосой девять ячеек хотбара и через зазор ячейка выбранной способности, в той же рамке и тех же цветах. Выбранная ячейка — светлая рамка и тёплый фон. Дополнительная рука, если в ней что-то есть, — отдельная ячейка слева от полосы, как в ванили. В левом верхнем углу ячеек хотбара — полупрозрачный уменьшенный (65%) номер ячейки с 1 (как клавиши 1–9): в классическом на каждой из девяти, в Morrowind на ячейке предмета в руке — номер выбранной ячейки, он меняется при пролистывании. Полоски здоровья, маны и сытости в обоих вариантах на прежнем месте, в левом нижнем углу.

## Изменения 0.4.1

Слоты основной сетки заполняются сверху вниз по столбцам. При обычном размере: первые три слота — первый столбец, следующие три — второй. Такой же порядок используется в сетках рюкзака, аксессуаров и хранилищ. Размер слотов и прокрутка учитывают новый порядок; серверные индексы предметов сохраняются.

## Изменения 0.4

- Удалено встроенное окно карты, его кнопка и перехват клавиши Xaero. World Map продолжает работать через собственный интерфейс.
- Переработана отрисовка слотов: предметы рисуются вместе со своим окном. Щелчок по фону и вывод окна наверх больше не скрывают иконки. Закрытые другим окном слоты не принимают ввод.
- Окна верстака, печи, зельеварки и аналогичных поддерживаемых машин имеют компактные исходные размеры и центрированную схему. Для результата крафта и печи показана стрелка; для работающих машин — прогресс и топливо. Раскладки разных типов контейнеров сохраняются отдельно.
- Атрибуты доступны и без Apothic. Строки отделены друг от друга, значение выровнено справа. Подсказка закреплена слева от окна; если места нет — справа, затем ограничивается экраном. Форматирование и источники модификаторов Apothic сохранены.
- Справа снизу расположены ползунки прозрачности окон (0–90%) и размера слотов (100–200%). Текст и предметы остаются читаемыми. Сетка перестраивается под ширину, скрытые строки прокручиваются. В узком окне хотбар сохраняется одним рядом; в очень маленьком общем меню рюкзака масштаб ограничивается доступным местом.
- Поиск и категории выделяют подходящие предметы золотистой рамкой с зелёной отметкой и затемняют остальные, включая хотбар. Булава входит в категорию оружия.
- «Дары» — отдельное перемещаемое и изменяемое по размеру окно. Сверху показаны иконки действующих эффектов и расовых преимуществ/ограничений; информация доступна по наведению. Снизу — список активируемых способностей с выбранной строкой. Расовые черты объединены в две иконки с полным описанием.
- Новый HUD в нижнем левом углу: здоровье — красное, мана Ars Nouveau — синяя, сытость — зелёная (с едой в руке мерцающий отрезок показывает, сколько она восстановит); рядом текущий предмет хотбара и выбранная способность. При наличии предмета в дополнительной руке видна отдельная иконка. Девять ячеек хотбара скрыты, обычная смена слота колесом/цифрами сохраняется. Иконки брони и полоска опыта с уровнем скрыты: они показаны в инвентаре, под моделью персонажа (см. ниже). Оверлеи AppleSkin на HUD скрыты; от него берётся только оценка еды в руке (с учётом модов, меняющих питательность) и его настройки показа еды в руке. Подсказки AppleSkin в инвентаре работают как обычно. Воздух и здоровье транспорта остаются штатными. Без Ars поле маны пустое; значения не выдумываются. F1 скрывает HUD; F8 возвращает штатный GUI/HUD. Творческий режим и наблюдатель сохраняют штатный HUD.

## Управление

| Действие | По умолчанию |
|---|---|
| Применить выбранный дар | \ |
| Следующий дар/заклинание | Page Down |
| Предыдущий дар/заклинание | Page Up |
| Сменить GUI и HUD | F8 |
| Поиск предметов | Ctrl + F |
| Передвинуть окно | Заголовок |
| Изменить размер | Любая сторона/угол |
| Поднять окно | Щелчок по его свободной области |
| Прокрутить сетку/список | Колесо |
| Скрыть/показать аксессуар | Ctrl + ПКМ по его слоту |

Клавиши меняются в настройках управления, категория **Civitatum HUD**. Клавиши способностей действуют в игровом мире; ввод поиска их не запускает. Кнопка «Дары» сверху показывает окно, в том числе при компактном GUI и открытом контейнере.

## Совместимость

Под моделью персонажа в окне экипировки — полоска опыта, под ней слева значение брони, по центру уровень (подсказки при наведении: очки опыта до следующего уровня, твёрдость брони).

**Camping:** кнопка с иконкой надетого рюкзака справа под полоской опыта показывает содержимое рюкзака вместе с основным инвентарём. Используется настоящее серверное меню: клики, разделение стеков, Shift и перетаскивание не добавляют фиктивных слотов. В меню рюкзака нет слотов брони и аксессуаров, поэтому броня и надетые аксессуары там только показываются; кнопка с нагрудником на том же месте возвращает к экипировке, где их можно менять. Рюкзак не открывается сам: инвентарь по E открывает меню Accessories (см. ниже).

**Accessories:** окно аксессуаров без заголовка всегда пристыковано слева от «Экипировки», отдельно его нельзя скрыть: в узком окне игры кнопка «Персонаж» прячет его вместе с экипировкой, а окно персонажа занимает их место. Оно перемещается вместе с ней за свою верхнюю полосу. Внутри — классический вид Accessories: столбец слотов, слева от него столбец косметических слотов. Его включает кнопка с бантиком (значок косметики Accessories) под основным столбцом, состояние запоминается. При включённой косметике самый левый столбец — косметическая броня Accessories (шлем, нагрудник, поножи, ботинки сверху вниз): предмет в ней рисуется вместо надетой брони, Ctrl+ПКМ по ней прячет эту часть брони на персонаже. Это встроенная возможность Accessories, отдельный мод (Cosmetic Armor Reworked) не нужен. Ширина окна следует за столбцами: один без косметики, три с ней (два в классическом меню Accessories, где косметической брони нет). Видно восемь рядов, остальные прокручиваются колесом над окном. Слоты существуют только в серверном меню Accessories, поэтому инвентарь по E сразу запрашивает его экспериментальный вариант: в нём, в отличие от Original, есть сетка крафта 2×2. Его слоты раскладываются классическим столбцом; косметика брони этого варианта не показывается (доступна в родном экране Accessories по F8). Один тик до ответа сервера окно пустое. Меню Original, открытое клавишей самого Accessories, тоже поддерживается, но крафта в нём нет. Слоты Aether 1.21.1 — это слоты Accessories, они показываются здесь же. Слот, скрытый на персонаже (Ctrl+ПКМ), затемнён и перечёркнут, в подсказке предмета — «Не отображается на персонаже». Скрытие работает для предметов, которые рисует Accessories; моды со своей отрисовкой (например, крылья Icarus) его не учитывают.

**Curios:** если открыть меню Curios его собственной клавишей, его слоты показываются в окне «Аксессуары» в два столбца. Колесо прокручивает ряды, а за последним рядом листает страницы Curios.

Вкладок «Вещи / Curios / Accessories / Aether» и кнопок страниц больше нет: основной инвентарь показывается всегда. Активность слотов считывается до изменения их экранных координат.

**Aether:** собственное меню аксессуаров Aether (восемь слотов в экипировке), если открыть его клавишей Aether, а также Altar, Freezer, Incubator. **Apothic Attributes:** атрибуты, скрытые записи, форматирование и доступные источники модификаторов. **Ars Nouveau:** синхронизированные текущая/максимальная и зарезервированная мана; стандартная полоса маны заменяется новой.

**Civitatum Character Creation:** настоящая активная расовая способность, её цена и откат. Запрос применения идёт на сервер; он проверяет условия. Если персонаж не выбран, список расовых способностей пуст.

## Миникарта Xaero и эффекты

**Что было.** Ванильные иконки эффектов рисуются в правом верхнем углу экрана — там же, где по умолчанию стоит миникарта Xaero. У Xaero есть настройка «Potion Effects Push Box»: невидимая рамка вокруг ванильных эффектов, которая сдвигает его интерфейсы. Поэтому при любом эффекте миникарта уезжала вниз, а с двумя рядами (полезные и вредные эффекты) — ещё ниже. Рамка миникарты была своей, Xaero, не в стиле окон инвентаря.

**Миникарта.**

- Не сдвигается от эффектов: рамку эффектов Xaero включает в одном месте, `XaeroMinimapCore.onRenderStatusEffectOverlayPost`, и этот вызов отменяется. Настройка `potion_effect_push_box` перестаёт на что-либо влиять.
- Своя рамка Xaero выключена при любом значении «Frame Style» (и «Frame Color» ни на что не влияет): в `MinimapRenderer.renderMinimap` его значение подменяется на последний стиль, «Off». Вместо неё вокруг карты рисуется рамка окон инвентаря (`MorrowindSkin.frame`): тёмный контур, золото сверху и слева, тень снизу и справа, 2 px снаружи карты. Прямоугольник карты берётся из того самого вызова, которым Xaero её рисует (`MinimapRendererHelper.drawMyTexturedModalRectPre` для квадратной, `drawTexturedElipseInsideRectangle` для круглой; в `renderMinimap` каждый вызывается один раз), через матрицу позы этого вызова — поэтому рамка совпадает с картой при любых масштабах и округлениях Xaero. Край карты между пикселями рамка перекрывает меньше чем на пиксель, а не оставляет щель. У круглой миникарты (Xaero «Shape» = Circle) рамка — кольцо вокруг круга в тех же цветах: контур снаружи, внутри золото на верхней левой половине и тень на нижней правой. Форму показывает то, какой из двух вызовов отрисовки карты сработал.
- Положение меняется как обычно — в редакторе HUD самого Xaero.

**Эффекты.** Слой эффектов (`VanillaGuiLayers.EFFECTS`) заменён своим:

- иконки — ванильные (фон, мигание за 10 секунд до конца, свои иконки модов через `IClientMobEffectExtensions`), но в 75% размера: 18 px вместо 24, между иконками 1 px, между рядами 2 px, как у ванили;
- до 7 иконок в ряд; ряды начинаются у левого края рамки миникарты (в 2 px от неё), на уровне её верха, и растут справа налево; восьмая иконка начинает следующий ряд;
- сначала полезные эффекты, вредные — с ряда под ними; порядок внутри — ванильный;
- если слева от миникарты не хватает места (её перенесли к левому краю), ряды встают справа от неё и растут вправо;
- если миникарты на экране нет (выключена, скрыта под F3 или экраном, эффект «No Minimap», запрет сервера) или Xaero не установлен, та же раскладка прижимается к правому верхнему углу экрана.

Эффекты едут за миникартой, в том числе прямо во время перетаскивания в редакторе HUD.

**Как узнаём, где миникарта.** Хук сразу после единственного вызова `MinimapProcessor.onRender` в `MinimapRenderer.render`: он стоит после всех ранних выходов, поэтому срабатывает только для нарисованной миникарты. Там же рисуется рамка и запоминается её прямоугольник. Координаты модуля — `ModuleRenderContext.x/y/w`, уже с учётом остальных рамок Xaero (например, полоски босса). Слой HUD Xaero зарегистрирован над `CAMERA_OVERLAYS`, то есть рисуется раньше эффектов, поэтому эффекты кадра видят миникарту того же кадра; в начале каждого кадра (`RenderGuiEvent.Pre`) запись сбрасывается.

Xaero's Minimap — необязательная зависимость: пять хуков лежат в отдельном конфиге `civitatum_hud.xaero.mixins.json`, который FML подключает только при установленном Xaero (`requiredMods` в `neoforge.mods.toml`). С Xaero все хуки обязательные: если он изменит эти методы, игра упадёт при запуске, а не будет молча работать без правки.

Сверено с Xaero's Minimap neoforge-1.21.1-26.6.0 и NeoForge 21.1.256 (`Gui.renderEffects`).

## Будущие заклинания

Сейчас в штатный список включена расовая способность Civitatum Character Creation. Книги заклинаний магических модов ещё не добавлены в этот список. Для их подключения есть публичный клиентский интерфейс `AbilitySelection.register(id, provider)`: провайдер возвращает способности с устойчивым ID, названием, иконкой, подсказкой, условием готовности и штатным серверным запросом применения. Выбор, клавиши и HUD используют один и тот же список. Наличие шкалы маны Ars само по себе не добавляет его заклинания.

## Прочие экраны

Поддерживаются сундуки/бочки/эндер-сундуки, воронки, раздатчики/выбрасыватели, шалкеры, печи/коптильни/плавильные печи, верстаки, зельеварки. Специализированные экраны наковальни, зачарования, торговли, камнереза и неподдерживаемых машин сохраняют свои элементы. Для штатной книги рецептов доступен F8 или «Обычный».

## Сборка

Из корня репозитория:

```sh
./gradlew :hud:build
./gradlew :hud:generateStoneTexture   # заново нарисовать каменный фон окон textures/gui/stone.png
```

Генератор фона лежит в `src/tools/java` и в jar мода не входит. Шум берётся из `java.util.Random` с постоянным зерном, поэтому каждый запуск рисует одну и ту же картинку.

Код и собственные текстуры — MIT, см. `LICENSE.txt` в корне репозитория; оригинальные ресурсы Morrowind и сторонние моды не включены.
